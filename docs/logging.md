# 로깅

아래가 이 프로젝트의 로깅 규약이다. 여기 없는 관례를 새로 만들지 않는다.

## 로거

- 클래스에 `@Slf4j`를 붙인다. `LoggerFactory.getLogger(...)`를 직접 부르지 않는다
- 값은 파라미터 바인딩(`{}`)으로 넘긴다. 문자열 연결(`+`)로 메시지를 만들지 않는다

## 레벨

| 레벨 | 언제 |
|---|---|
| `error` | 처리하지 못한 예외. 서버가 잘못한 것 |
| `warn` | 클라이언트 입력이 잘못된 것. 4xx로 응답하는 모든 경로 |
| `info` | 기동·설정 로드 같은 수명주기 이벤트와 외부 연동 결과. 요청마다 남기지 않는다 |
| `debug` | 개발 중 확인용. 운영 프로파일에서 켜지 않는다 |

- 예외 객체를 마지막 인자로 넘기는 것은 `error`일 때만이다. `log.error("...", e.getMessage(), e)`
- `warn`에는 스택트레이스를 붙이지 않는다. 4xx는 서버 잘못이 아니라서 스택은 노이즈만 된다

## 메시지 형식

- 대괄호 태그로 시작한다. `[검증 실패]` `[파라미터 누락]` `[ApiException]`
- 태그는 한국어로 쓴다. 뒤따르는 값은 `키=값`으로 붙이고 쉼표로 나눈다

## 남기지 않는 값

- **참여자의 현재 위치·출발지 좌표** (CLAUDE.md 1번 규칙)
- **요청 record를 통째로 넘기지 않는다.** `log.info("{}", req)` 한 줄이면 record의 `toString()`이
  좌표를 그대로 출력한다. 필요한 필드만 골라서 찍는다 (`dto.md`)
- **외부 연동(지도 API 등) 호출 로그에 요청 URL·파라미터를 남기지 않는다.**
  쿼리스트링에 좌표가 들어간다. 결과 상태와 소요시간만 남긴다

### 예외 메시지를 타고 나가는 경로

`GlobalExceptionHandler`의 `Exception` 핸들러는 `e.getMessage()`와 스택트레이스를 함께 남긴다.
좌표를 담아 지도 API를 호출하기 시작하면, 그 호출이 실패했을 때 요청 URL이나 파라미터가
예외 메시지에 실려 이 경로로 나갈 수 있다. `log`를 직접 쓰지 않아도 발생한다.

- 지도 API 호출은 클라이언트 경계에서 잡아 자체 예외로 바꿔 던진다.
  원본 예외를 그대로 위로 올리지 않는다
- 바꿔 던지는 예외의 메시지에 좌표를 넣지 않는다. 원인은 `ErrorCode`로 구분한다
